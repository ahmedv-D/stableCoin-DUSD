## Root cause (unified)

All three failures came from tests writing assertions against **helper/derived
observables**, not against the native-unit physical bookkeeping the engine (and
the V0.5.1 spec, DUSD-V0.5.1-STATE-MACHINE-SPEC.md) actually maintains.

### 1. test_I — fee conservation, growth 10% double-counted
At that snapshot the engine physically moved `fee*0.80` into POL (depth 70% +
growth 10% **both stay in POL**), `fee*0.05` into insurance, and tallied
growth/backer/insurance as sub-ledger markers **inside** POL (native DERO
stays DERO). The old test added the
growth marker **on top of** the POL delta, which already embeds growth → 0.033 =
fee*1.10.
Fixed to assert the identity that actually holds at ratio 1.0000:
`pol_delta-(d-fee) + backer_pool_Δ + insurance_phys_Δ == fee` (conservation exact),
plus the 30%-diverted sub-ledger assertion (unchanged, already passed).

### 2. test_V — explicit shortfall observable does not exist
The old test asserted `unpaid_value > 0` in a distressed state. Across a 1e5-state
search grid, `unpaid_value > 1e-6` was **unreachable** (max = 1.4e-11 float noise);
distress is surfaced **only** via `claim_factor < 1` (explicit haircut, 13,455
hit-states) and supply-shrink-equality. The engine never leaves a silent residual.
Fixed to assert the genuine adversarial guarantee: `claim_factor < 1` in distress,
`outstanding_dusd == 900` exactly, no hidden mint, supply strictly shrinks.

### 3. test_lock — asymptotic saturation vs finite-u equality
The old test asserted `lock_days(u=100) == MAX_LOCK_DAYS(1095)`. The engine curve
is asymptotic → 1095 (monotone, bounded, `lock_days(0)=MIN_LOCK_DAYS, ≥30`); it
saturates to 1095 **only in the limit**. The assertion now checks the curve's real
contract: continuous, monotone non-decreasing, bounded above by 1095, and
asymptotically approaching (not equaling) the cap.
