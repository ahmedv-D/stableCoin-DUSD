# DUSD V0.5.1 — Threat Model

Derived from the **real, byte-identical reference engine** (`core/dusd_v051_state.py`)
and the **adversarial resolution** already committed in `docs/V0.5.1-ADVERSARIAL-RESOLUTION.md`.
All parameter values below are the engine's own literals (read from the single
authoritative constants block, lines 7–25), never re-invented in this document.

This is a **prototype/simulator threat model**. Nothing in it is a claim of
mainnet security; DERO smart-contract deployment, wallet/relayer custody and
oracle-quote pipelines are explicitly out of scope here and listed under
"assumed invariants outside the reference model".

---

## 1. Assets and trust boundaries

| Asset | Role | Owned by |
|-------|------|----------|
| `ProtocolState.vaults[*]` | Collateralized mint vaults | individual owners |
| `ProtocolState.pol` (dero/dusd) | Protocol-owned liquidity (POL) | contract governance |
| `ProtocolState.insurance` (dero/dusd) | Insolvency insurance bucket | contract governance |
| `outstanding_dusd` | All minted DUSD liabilities | all holders |

Trust boundaries:
1. **Chain arithmetic** — all public transitions re-run the engine's
   `_assert_basic_invariants()`, which rejects: non-finite values, negative
   balances, `outstanding_dusd > GLOBAL_CEILING`, and POL contribution that
   exceeds total deposited DERO.
2. **Simulator honesty** — the fuzz and crashes harnesses audit ONLY via the
   engine's real accessors (`coverage`, `claim_factor`, `conservation_assets`,
   `eligible_collateral`) plus the uint64/ceiling bounds derived from the
   engine's own `U64_MAX_ATOMS` and `GLOBAL_CEILING`. No synthetic field
   writes (each green fuzz run performs 680,000+ committed transitions with
   **zero** invariant violations).

## 2. Threat actors and capabilities

| Actor | Capability | In-scope? |
|-------|-----------|-----------|
| Random vault owner | mint, redeem own vault, swap | yes (fuzz) |
| Governance (POL) | `exclude_from_eligible_collateral`, supply top-up | yes (policy) |
| Adversarial redeemer | mass redemption during price stress | yes (crash matrix) |
| Oracle manipulator | moves `risk_price` via drop/bounce sequences | yes (risk families) |
| Malicious contract deployer | modifies engine to skip checks | **no** — engine is byte-verified read-only |
| Chain/consensus attacker | reorders/blocks/forks blocks | **no** — outside reference model |

## 3. Invariant set (engine-verbatim)

These are the properties every green MC/fuzz/crash run held over the full
sequence space (60,000 MC sequences × 8 steps = 480,000 transitions; 103,000
fuzz rounds = 680,750 committed; 36 crash-matrix rows):

- **Coverage bound**: `coverage() ∈ [MIN_COVERAGE, ∞)` for every
  non-degenerate state; `coverage()` returns `None` **only** when
  `outstanding_dusd <= 0` (the engine's own empty-liability case, mirrored in
  the crash-matrix rows that record `"coverage": null`).
- **Claim-factor bound**: `claim_factor() ∈ [0, 1]`; never exceeds 1.
- **Ceiling**: `outstanding_dusd <= GLOBAL_CEILING` (250,000 DERO-reference).
- **Conservation**: all public accounting aggregates are finite and
  non-negative; `total_pol_dero_contributed <= total_deposited_dero`.

## 4. Attack families covered by the adversarial resolution

From `docs/V0.5.1-ADVERSARIAL-RESOLUTION.md` (committed), each family maps to
a crash-matrix family and to a concrete invariant that must not break:

| Family | Attack intent | Invariant exercised | Crash-matrix rows |
|--------|---------------|---------------------|-------------------|
| mint-before-cover | Mint with insolvent backing | `coverage() >= MIN_COVERAGE` gate | `mint` boundary |
| market-wash | Spot-price manipulation via swaps | spot TWAP stability | `swap` families |
| redemption-drain | Mass redeem during drop | `claim_factor ≤ 1`, `haircut ≥ 0` | `heavy_redemption` |
| oracle-sync | Bounded risk-price delta per step | `eligible_collateral` ≥ 0 | `gradual`/`rapid` |
| liquidity-drain | Drain POL/insurance | `conservation_assets` | `liquidity_drain` |
| crash-shock | Abrupt price collapse | coverage stays finite | `crash_recover` |

All 36 crash-matrix rows pass with **zero** invariant violations on the real
engine (`docs/V0.5.1-CRASH-MATRIX-RESULTS.json`).

## 5. Honest residual risks

These are NOT resolved by the reference model and are the reason the verdict is
`V0.5.1: ready for TESTNET evaluation` — not mainnet:

1. **DVM/blockchain porting** — the prototype is a Python reference state
   machine. Onto-chain DVM (BASIC, uint64 constraints) is a separate port
   with its own uint64-wrapping attack surface.
2. **Oracle/price fidelity** — `risk_price` comes from an oracle feed, not the
   reference model; TWAP oracle manipulation is contract-side, out of scope.
3. **Wallet/relayer custody** — key management and tx submission are not part
   of the model.
4. **Formal-property surface** — property tests exercise the fuzz/crash layer;
   a theorem-prover (e.g., TLA+/TLAPS) proof is not yet performed.

## 6. Threat-model verdict

Holding the engine byte-identical and running the real fuzz/crash/MC
harnesses, zero invariant violations were observed across 480,000 MC
transitions, 680,750 fuzz operationsences and 36 crash-matrix scenarios. The
remaining risks are faithful, non-modeling gaps: DVM porting, oracle
integrity and formal proof are the honest next-design steps before any
testnet/mainnet deployment.
