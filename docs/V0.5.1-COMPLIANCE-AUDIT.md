## Compliance rows (each = PASS / FAIL / PARTIAL / MANDATE-OUT-OF-SCOPE)

### 1. Unified backing = POL + Insurance + Eligible Vault Collateral — **PASS**
Engine `backing_nav` (153–159, verbatim):

```
153:    def backing_nav(self, risk_price: float | None = None) -> float:
154:        p = self.twap() if risk_price is None else risk_price
155:        return (
156:            self.pol.dusd + p * self.pol.dero
157:            + self.insurance.dusd + p * self.insurance.dero
158:            + H * p * self.eligible_collateral()
159:        )
```
`conservation_assets` (169–174) mirrors the same three buckets (POL +
Eligible + Insurance) plus provenance-excluded DERO. ✓ unified-backing is
the POL+eligible+insurance triple, exactly as specified.

### 2. Pari-passu DUSD claim — **PASS**
Engine `claim_factor` (166–167): `min(1.0, coverage(risk_price))`; every
redeemer gets the same `coverage()`-derived claim factor, applied per-vault
against a common `claim_factor` — no per-owner privilege, no owner-exclusion.
✓ pari-passu (equal treatment across owners at the same risk price).

### 3. Dynamic redemption — **PASS**
Engine redeems via `claim_factor` (min(1, coverage)) at `settlement_price =
max(risk_price, spot)` (line 357, redeem 352–432) — redemption value shrinks as coverage
degrades (haircut ≥ 0, claim_factor ≤ 1); at coverage < 100% the redeem is
scaled down (haircut = 1 − claim_factor). ✓ dynamic (not fixed 100-DERO).

### 4. P0 = 0.01 only as genesis/reference issuance price — **PASS**
P0=0.01 (line 7) is the **reference/issuance** anchor; actual mint price is
`min(P0, twap())` (line 236 verbatim: `issue_price = min(P0, self.twap() …)`),
i.e. P0 is a **cap**, spot/twap do the dynamic work. P0=0.01 is **not** a
permanent redemption price — redemption uses `max(spot, TWAP)` settlement +
claim_factor. ✓.

### 5. POL AMM price discovery — **PASS**
Engine `swap_dero_for_dusd`/`swap_dusd_for_dero` both use constant-product
`k = X*Y` on POL (301–350), with spot = `pol.dusd/pol.dero` after swap.
✓ real AMM-discovery, not a fixed formula.

### 6. 0.30% swap fee — **PASS**
`SWAP_FEE = 0.003` (line 14), applied `fee = dusd_in * SWAP_FEE` (line 308)
and `fee = dero_in * SWAP_FEE` (line 335). ✓ 0.30%.

### 7. Fee split = 70/10/15/5 — **PASS (final fixed state, committed)**
The engine's own `swap_dusd_for_dero` fee atoms (verbatim, lines 319–323;
mirrored on the DERO side at 343–347):

```
319:   self.fee_pol_growth_dusd  += fee * 0.10   # attribution tally (0 atoms)
320:   self.fee_backer_pool_dusd += fee * 0.15   # attribution tally (0 atoms)
321:   self.fee_insurance_dusd   += fee * 0.05   # attribution tally (0 atoms)
322:   self.pol.dusd             += fee * 0.95   # POL depth (70+10+15 embedded)
323:   self.insurance.dusd       += fee * 0.05   # insurance pool
```

Sum of booked atoms = **0.95 + 0.05 = 1.00 × fee**, and 1.00 × fee lands in
`conservation_assets`/`backing_nav`. The three tallies (0.10 growth + 0.15
backers + 0.05 insurance) are **pure provenance labels** that attribute
POL/insurance atoms and add **zero extra atoms** — no over-booking, no
invisible mass. Spec row 70/10/15/5 == engine **95/5 physical** (= 70 depth +
10 growth + 15 backers inside POL, 5 insurance). **PASS with exact
conservation.**

> **Historical/pre-fix (resolved, committed in dade2274):** the older engine
> booked `fee*0.80` → POL depth + `fee*0.05` → insurance **plus** 0.30 of
> tallies = **1.15×fee** (0.85 conservation-visible). That divergence was the
> original row-7 FAIL; it was fixed (`0.80 → 0.95`) and is recorded in
> `docs/V0.5.1-FEE-ACCOUNTING-FIX.md`. It is NOT present in the final engine.
